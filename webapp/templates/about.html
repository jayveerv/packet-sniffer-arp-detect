How it works

Every packet is decoded (Ethernet, ARP, IP, TCP, UDP, ICMP, DNS, DHCP, HTTP). ARP packets also go to the spoofing detector, which keeps an IP → MAC table.

Detection rules · MITRE ATT&CK {{ mitre_id }} ({{ mitre_name }})

AlertWhenSeverity
IP-MAC conflictAn IP that was at one MAC is claimed by a different MAC (within {{ 300 }} s of last being seen).High
Whitelisted MAC mismatchA trusted IP (for example the router) is claimed by a MAC that is not in the whitelist.High
Gratuitous ARP floodMore than {{ st.threshold }} gratuitous ARPs from one MAC within {{ st.window }} s.High
Unsolicited ARP replyAn "is-at" reply without a matching "who-has" request in the last 2 s. Medium when it also changes a mapping.Low / Medium
IP reassignedA new MAC takes an IP that was silent for more than 300 s: normal DHCP reuse, reported for context.Low

Reducing false positives

  • A single gratuitous ARP (a device announcing itself after DHCP) is never an alert on its own.
  • ARP probes with sender 0.0.0.0 are ignored.
  • IP reuse after a long silence is Low, not High.
  • Trusted IP=MAC pairs and the flood threshold can be set on the dashboard.
  • Repeated alerts are grouped and counted instead of flooding the panel.
  • Still expect noise from VRRP/HSRP router failover, virtual-machine bridges and phone hotspots: whitelist them.
